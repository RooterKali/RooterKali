What I find

Findings that changed how a team thinks about its auth.

Every item below was manually discovered and validated. Impact was reproduced through the actual application before it was reported.

SSO authentication bypass

High

A flaw in the SSO trust flow allowed unauthenticated access to an internal admin dashboard, turning an external entry point into privileged application control.

Broken authentication SSO Privilege escalation

OAuth code leakage via open redirect

High

An insufficiently validated nextUrl parameter on the login flow allowed redirection to attacker-controlled origins, leaking the authorization code and enabling full account takeover.

OAuth 2.0 Open redirect Account takeover

Unauthenticated admin panels

High

Privileged administration surfaces were reachable without authentication, exposing internal application assets and functionality to anonymous users.

Access control Exposed admin Broken access control

Dependency confusion in supply chain

Medium

Confirmed dependency confusion across package ecosystems, where references to internal packages could be resolved to attacker-controlled public ones. One case remains open with the target program.

Supply chain Dependency confusion Package namespace

Source map and secret exposure

Low

Info disclosure Source maps Secret leakage

Session fixation and IDOR

Tools and projects

Tooling

MapGhost

A source-map-based dependency-confusion scanner I wrote to find exposed internal package references across a large asset list. The implementation is private; the method, report format, and sample output are public.

  • Crawls targets for exposed .js.map files across 7 operating modes
  • Extracts package references with a Node AST parser instead of regex matching
  • Scores findings across 4 severity tiers with resume state and scheduled scans
  • Emits JSON and HTML reports with Discord webhook alerting

Triage methodology

npm-package-validation

A published triage skill that separates genuine npm usage from false positives before a report is filed. Most dependency-confusion noise dies at this step, and this is what keeps my duplicate rate honest.

  • Source-origin-first validation before any runtime assumption
  • Runtime import and package-shape checks
  • Claimability-based verdicts: real, not takeoverable, or noise
